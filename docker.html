This is called

Virtualization

A technique that allows running multiple environments on a single physical server.

Most modern applications rely on it, including the cloud services you use every day.

Two technologies

There are two ways to do this

🖥️ Virtual machines

Split the machine into separate, complete computers.

📦 Containers

Split it into lightweight boxes that share one operating system.

Both are powerful, but they differ in benefits and use cases.

When to use

Virtual machines

  • Different operating systemsWindows and Linux on the same hardware
  • Legacy applicationsApps that need an old or outdated OS
  • High security demandsVMs offer complete isolation
When to use

Containers

  • MicroservicesApps built from independent parts
  • CI/CD pipelinesFast start-up for frequent testing and deploying
  • PortabilityMove your app between environments, it runs the same everywhere
  • The cloudEasy to deploy, great for cloud and hybrid setups

Recap

So what is Docker? 🐳

An open-source containerization platform.

It packages your software and everything it needs into one standard unit: a container.

Containers share the host's kernel, so they're efficient and lightweight.

Basic concepts

Three words to remember

📜 Image

The blueprint: a read-only template with everything the app needs.

📦 Container

A running instance of an image. Make as many as you like.

🏛️ Registry

Where images are shared, like Docker Hub: GitHub for images.

Today's game image lives in GitHub's registry: ghcr.io
Zooming in on

Docker images

The fundamental building blocks of containers. Immutable, read-only templates containing everything needed to run an application: the operating system, application code, runtime and dependencies.

They're built from a Dockerfile, layer by layer, and stored in registries like Docker Hub.

A simple example

Reading a Dockerfile

FROM python:3.12-slimWORKDIR /appCOPY requirements.txt .RUN pip install -r requirements.txtCOPY . .CMD ["python", "main.py"]
  • FROMStart from a base image: a small Linux with Python
  • WORKDIRWork inside the folder /app
  • COPYCopy the list of libraries in
  • RUNInstall those libraries
  • COPYCopy your own code in
  • CMDWhat to run when a container starts
docker build -t my-app . turns this recipe into an image. Every line becomes a layer.
If you know Python...

Image = class, container = instance

class WebApp:        # the image    ... app1 = WebApp()       # container 1app2 = WebApp()       # container 2

One class, many objects.

One image, many containers.

Each container is its own separate copy, but they all come from the same blueprint.

Zooming in on

Docker containers

A running instance of a Docker image. An isolated runtime environment where applications run without interfering with each other or the host system.

Each container has its own file system, networking and process space, but shares the host's kernel.

The image is the blueprint. The container is the blueprint brought to life. ▶️
