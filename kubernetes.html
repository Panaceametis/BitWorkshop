A quick look back

Running one container

Docker is a set of tools that lets you create, edit and run containers.

A container is just an application in a small box, together with everything it needs to run.

Because everything is inside the box, it runs the same on any machine.

Starting it is one command: docker run my-app. Easy. ✅

📦 Container
🧑‍💻Your application
📚Libraries it needs
⚙️Settings
Now imagine...

50,000 containers

You have to start 50,000 containers. Way too many for one server.

So you spread them out: 500 servers, 100 containers each. That's 500 logins and a lot of commands. 😵

The containers need to talk to each other? Then you set up all the network connections between them.

With 50,000 running, something will break, somewhere. Every day you hunt down the broken ones and restart them by hand.

Not a fun life. 😩

Each purple box is a server, each green block a container

Kubernetes

A system created to orchestrate containers: it automates deploying, scaling and managing them across many servers.

Docker runs a container. Kubernetes runs thousands of them, and keeps them healthy.

Often written as K8s: a K, then 8 letters, then an s.

Automation

What Kubernetes does for you

🚀 Starts them

All your containers, spread over many servers at once

🌐 Connects them

Sets up the networks between containers

👀 Watches them

Checks they work, and restarts whatever breaks

📈 Scales up

A news article sends extra traffic? It adds containers

📉 Scales down

Closes the containers you don't need anymore

⚖️ Balances traffic

Sends traffic to the servers that have room

The big idea

You say what, Kubernetes figures out how

✋ By hand

docker run -d my-app  # server 1docker run -d my-app  # server 2docker run -d my-app  # server 3... 49,997 more

You list every step yourself.

🧾 With Kubernetes

image: my-appreplicas: 50000

This is called the declarative approach. The file you write it in uses YAML.

Zooming in on

Pods

Kubernetes' own way of running containers. A pod is the smallest deployable unit in Kubernetes, and represents a single instance of an application.

A container is a single unit. A pod is a box that can hold one or more containers, so you can manage them as one.

The pod gets one IP address. The containers inside it talk to each other via localhost.

A simple example

Describing a pod in YAML

apiVersion: v1kind: Podmetadata:  name: my-podspec:  containers:    - name: web      image: nginx      ports:        - containerPort: 80
  • kindWhat to create: a Pod
  • metadataIts name: my-pod
  • specWhat you want inside it
  • containersThe container(s) in this pod
  • imageThe image to run, like docker run nginx
  • portsThe port the app listens on
A pod is a Kubernetes object. To create one, you declare what it needs in YAML, then run kubectl apply -f pod.yaml.
Zooming in on

Nodes

A node is just a machine, physical or virtual, that hosts pods.

One node can run many pods. Every pod runs on a node.

Nodes together form a cluster: cluster → nodes → pods → containers.

Keeping copies running

Deployments

apiVersion: apps/v1kind: Deploymentmetadata:  name: webspec:  replicas: 3  template:    spec:      containers:        - name: web          image: my-app:v2
  • kind: DeploymentManages a set of identical pods for you
  • replicas: 3Always keep 3 copies running. One dies? A new one starts.
  • templateWhat each pod looks like, just like the pod file
  • image: my-app:v2Change the version and Kubernetes replaces the pods one by one: a rollout. Something wrong? Roll back.
